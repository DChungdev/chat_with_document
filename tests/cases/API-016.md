| Thuộc tính | Giá trị |
|---|---|

| **Thư mục artifact** | `tests/reports/API-016/` |
| **Nguồn** | [docs/testing/Test_Plan.md](../../docs/testing/Test_Plan.md) |

## Mục tiêu

Mọi lỗi đầu vào trả JSON `problem+json` thường (không phải SSE).

## Điều kiện tiên quyết

- Máy chủ đang chạy tại http://127.0.0.1:8000 (`GET /health` → 200; devserver: adapter LLM/embedding giả, dữ liệu trong bộ nhớ).
- Tài khoản dev **mới, tên duy nhất** cho case này (vd `tc<mã-thời-gian>`), tạo bằng `tc.apiLogin()` hoặc form đăng nhập.
- Tài khoản đã xác nhận thông báo dữ liệu (`GET /api/v1/data-notice` → lấy `version` → `POST /api/v1/data-notice/acceptances`) — với UI dùng `tc.acceptNotice()`.
- Đã tạo hội thoại.

## Các bước và kết quả mong đợi

| # | Hành động | Kết quả mong đợi |
|---|---|---|
| 1 | Hỏi khi **chưa có** tài liệu `ready` | `422`, `code=NO_READY_DOCUMENTS` |
| 2 | Tải `baogia.pdf`, chờ `ready`; hỏi với `question=""` hoặc toàn khoảng trắng | `400`/`422 VALIDATION_ERROR` |
| 3 | Hỏi với câu hỏi dài hơn `maxQuestionLength` (+1 ký tự) | `413`, `code=QUESTION_TOO_LONG` |
| 4 | Hỏi với `documentIds` chứa tài liệu chưa `ready` (dùng `scan.pdf` → `error`) | `409 DOCUMENT_NOT_READY` (hoặc mã tương đương; ghi thực tế) |
| 5 | Mọi phản hồi lỗi ở trên | `Content-Type: application/problem+json`, không phải `text/event-stream` |

## Tiêu chí đạt

Tất cả các bước đều đạt kết quả mong đợi. Bất kỳ bước nào lệch → case **FAIL**.

## Nhiệm vụ của agent

Bạn là agent thực thi test case này. **Phải** tạo đủ các artifact sau trong thư mục riêng `tests/reports/API-016/`:

| Artifact | Đường dẫn | Yêu cầu |
|---|---|---|
| Test report | `tests/reports/API-016/report.md` | Kết quả tổng, từng bước (mong đợi vs thực tế), lỗi phát hiện, ghi chú |
| Ảnh chụp màn hình | `tests/reports/API-016/screenshots/*.png` | Ít nhất **một ảnh cho mỗi bước** (khung tự chụp); ảnh bước lỗi có tiền tố `fail-` |
| Video | `tests/reports/API-016/video/API-016.webm` | Quay toàn bộ quá trình chạy (khung tự quay) |
| Kết quả máy đọc | `tests/reports/API-016/result.json` | Tự sinh |
| Mã chạy | `tests/reports/API-016/run.mjs` | Script bạn viết để thực thi case này (giữ lại để chạy lại) |

**Quy trình:**
1. Đọc [tests/README.md](../README.md) (cách dùng khung `tests/tools/tc.mjs`: `startCase`, `tc.step`, `tc.http`, `tc.login`, `tc.axe`…).
2. Xác nhận máy chủ `http://127.0.0.1:8000/health` trả `200`. Nếu chưa chạy, khởi động theo README (không đổi mã sản phẩm).
3. Viết `tests/reports/API-016/run.mjs` dùng `startCase("API-016", { title: "…" })`. **Mỗi dòng ở bảng “Các bước” là một `tc.step(tên, mong_đợi, fn)`**; dùng `expect` để kiểm tra, trả về chuỗi mô tả kết quả thực tế. Case API dùng `tc.http()` để mỗi request/response có ảnh bằng chứng; case UI dùng ảnh chụp giao diện.
4. Chạy `node tests/reports/API-016/run.mjs` từ thư mục gốc repo; mở vài ảnh chính để chắc chắn chúng thật sự là bằng chứng của bước đó.
5. Phân loại kết quả trung thực:
   - Sản phẩm sai so với “Kết quả mong đợi” → giữ **FAIL**, ghi `tc.defect("mô tả + cách tái hiện + mức độ")`. **Không** sửa mã sản phẩm, **không** nới kỳ vọng để “cho đạt”.
   - Lỗi do script/selector của bạn → sửa script và chạy lại.
   - Không thể kiểm chứng (thiếu môi trường, ngoài khả năng của devserver) → ghi rõ trong `tc.note(...)` và trong kết luận là **chưa kiểm chứng** (không ghi PASS).
6. Dọn dẹp trạng thái dùng chung (ví dụ bật lại kill switch) trong `finally`.
7. Kết thúc bằng một câu trả lời ngắn: **ID · PASS/FAIL/chưa kiểm chứng · đường dẫn `report.md` · lỗi phát hiện (nếu có)**.

**Tiêu chí hoàn thành artifact:** `report.md`, ≥ 1 ảnh mỗi bước, 1 video `.webm` không rỗng và `result.json` đều tồn tại; report không chứa token/secret/nội dung nhạy cảm.
