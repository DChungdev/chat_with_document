# API-012 — GET /documents/{id}: tồn tại và không tồn tại

| Thuộc tính | Giá trị |
|---|---|
| **ID** | API-012 |
| **Loại** | API black-box |
| **Ưu tiên** | P0 |
| **Truy vết** | US-102, US-402 · IF-04 · API-012 |
| **URL kiểm thử** | http://127.0.0.1:8000 |
| **Thư mục artifact** | `tests/reports/API-012/` |
| **Nguồn** | [docs/testing/Test_Plan.md](../../docs/testing/Test_Plan.md) |

## Mục tiêu

Poll một tài liệu; id lạ hoặc của người khác → `404`.

## Điều kiện tiên quyết

- Máy chủ đang chạy tại http://127.0.0.1:8000 (`GET /health` → 200; devserver: adapter LLM/embedding giả, dữ liệu trong bộ nhớ).
- Hai tài khoản A và B, cả hai đã xác nhận thông báo; A đã tải `baogia.pdf`.

## Các bước và kết quả mong đợi

| # | Hành động | Kết quả mong đợi |
|---|---|---|
| 1 | A: `GET /documents/{id}` | `200`, đúng schema `Document` |
| 2 | B: `GET /documents/{id của A}` | `404`, `code=NOT_FOUND` (không lộ sự tồn tại) |
| 3 | A: `GET /documents/<uuid ngẫu nhiên>` | `404` |
| 4 | A: `GET /documents/khong-phai-uuid` | `422`/`400` problem+json |

## Tiêu chí đạt

Tất cả các bước đều đạt kết quả mong đợi. Bất kỳ bước nào lệch → case **FAIL**.

## Nhiệm vụ của agent

Bạn là agent thực thi test case này. **Phải** tạo đủ các artifact sau trong thư mục riêng `tests/reports/API-012/`:

| Artifact | Đường dẫn | Yêu cầu |
|---|---|---|
| Test report | `tests/reports/API-012/report.md` | Kết quả tổng, từng bước (mong đợi vs thực tế), lỗi phát hiện, ghi chú |
| Ảnh chụp màn hình | `tests/reports/API-012/screenshots/*.png` | Ít nhất **một ảnh cho mỗi bước** (khung tự chụp); ảnh bước lỗi có tiền tố `fail-` |
| Video | `tests/reports/API-012/video/API-012.webm` | Quay toàn bộ quá trình chạy (khung tự quay) |
| Kết quả máy đọc | `tests/reports/API-012/result.json` | Tự sinh |
| Mã chạy | `tests/reports/API-012/run.mjs` | Script bạn viết để thực thi case này (giữ lại để chạy lại) |

**Quy trình:**
1. Đọc [tests/README.md](../README.md) (cách dùng khung `tests/tools/tc.mjs`: `startCase`, `tc.step`, `tc.http`, `tc.login`, `tc.axe`…).
2. Xác nhận máy chủ `http://127.0.0.1:8000/health` trả `200`. Nếu chưa chạy, khởi động theo README (không đổi mã sản phẩm).
3. Viết `tests/reports/API-012/run.mjs` dùng `startCase("API-012", { title: "…" })`. **Mỗi dòng ở bảng “Các bước” là một `tc.step(tên, mong_đợi, fn)`**; dùng `expect` để kiểm tra, trả về chuỗi mô tả kết quả thực tế. Case API dùng `tc.http()` để mỗi request/response có ảnh bằng chứng; case UI dùng ảnh chụp giao diện.
4. Chạy `node tests/reports/API-012/run.mjs` từ thư mục gốc repo; mở vài ảnh chính để chắc chắn chúng thật sự là bằng chứng của bước đó.
5. Phân loại kết quả trung thực:
   - Sản phẩm sai so với “Kết quả mong đợi” → giữ **FAIL**, ghi `tc.defect("mô tả + cách tái hiện + mức độ")`. **Không** sửa mã sản phẩm, **không** nới kỳ vọng để “cho đạt”.
   - Lỗi do script/selector của bạn → sửa script và chạy lại.
   - Không thể kiểm chứng (thiếu môi trường, ngoài khả năng của devserver) → ghi rõ trong `tc.note(...)` và trong kết luận là **chưa kiểm chứng** (không ghi PASS).
6. Dọn dẹp trạng thái dùng chung (ví dụ bật lại kill switch) trong `finally`.
7. Kết thúc bằng một câu trả lời ngắn: **ID · PASS/FAIL/chưa kiểm chứng · đường dẫn `report.md` · lỗi phát hiện (nếu có)**.

**Tiêu chí hoàn thành artifact:** `report.md`, ≥ 1 ảnh mỗi bước, 1 video `.webm` không rỗng và `result.json` đều tồn tại; report không chứa token/secret/nội dung nhạy cảm.
