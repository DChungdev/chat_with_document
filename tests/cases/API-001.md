## Mục tiêu

Xác nhận `/config` trả đủ giới hạn, `qaEnabled`, `noticeVersion`, `noticeAccepted` đúng schema để SPA không phải hard-code giới hạn.

## Điều kiện tiên quyết

- Máy chủ đang chạy tại http://127.0.0.1:8000 (`GET /health` → 200; devserver: adapter LLM/embedding giả, dữ liệu trong bộ nhớ).
- Tài khoản dev **mới, tên duy nhất** cho case này (vd `tc<mã-thời-gian>`), tạo bằng `tc.apiLogin()` hoặc form đăng nhập.

## Các bước và kết quả mong đợi

| # | Hành động | Kết quả mong đợi |
|---|---|---|
| 1 | Gọi `GET /api/v1/config` không có token | `401` (problem+json, `code` UNAUTHENTICATED) |
| 2 | Gọi `GET /api/v1/config` với token | `200`; có `qaEnabled=true`, `noticeVersion`, `noticeAccepted=false`, và các giới hạn tệp/câu hỏi (mặc định: 20 MB/tệp, 50 tệp, câu hỏi ≤ 2000 ký tự) |
| 3 | Xác nhận thông báo rồi gọi lại `/config` | `noticeAccepted=true` |
| 4 | Kiểm tra header phản hồi | Có `X-Request-Id` |

## Tiêu chí đạt

Tất cả các bước đều đạt kết quả mong đợi. Bất kỳ bước nào lệch → case **FAIL**.

## Lưu ý

- Tên trường JSON là camelCase. Nếu tên trường thực tế khác tài liệu, ghi lại giá trị thực và đánh FAIL/ghi chú lệch tài liệu.

## Nhiệm vụ của agent

Bạn là agent thực thi test case này. **Phải** tạo đủ các artifact sau trong thư mục riêng `tests/reports/API-001/`:

| Artifact | Đường dẫn | Yêu cầu |
|---|---|---|
| Test report | `tests/reports/API-001/report.md` | Kết quả tổng, từng bước (mong đợi vs thực tế), lỗi phát hiện, ghi chú |
| Ảnh chụp màn hình | `tests/reports/API-001/screenshots/*.png` | Ít nhất **một ảnh cho mỗi bước** (khung tự chụp); ảnh bước lỗi có tiền tố `fail-` |
| Video | `tests/reports/API-001/video/API-001.webm` | Quay toàn bộ quá trình chạy (khung tự quay) |
| Kết quả máy đọc | `tests/reports/API-001/result.json` | Tự sinh |
| Mã chạy | `tests/reports/API-001/run.mjs` | Script bạn viết để thực thi case này (giữ lại để chạy lại) |

**Quy trình:**
1. Đọc [tests/README.md](../README.md) (cách dùng khung `tests/tools/tc.mjs`: `startCase`, `tc.step`, `tc.http`, `tc.login`, `tc.axe`…).
2. Xác nhận máy chủ `http://127.0.0.1:8000/health` trả `200`. Nếu chưa chạy, khởi động theo README (không đổi mã sản phẩm).
3. Viết `tests/reports/API-001/run.mjs` dùng `startCase("API-001", { title: "…" })`. **Mỗi dòng ở bảng “Các bước” là một `tc.step(tên, mong_đợi, fn)`**; dùng `expect` để kiểm tra, trả về chuỗi mô tả kết quả thực tế. Case API dùng `tc.http()` để mỗi request/response có ảnh bằng chứng; case UI dùng ảnh chụp giao diện.
4. Chạy `node tests/reports/API-001/run.mjs` từ thư mục gốc repo; mở vài ảnh chính để chắc chắn chúng thật sự là bằng chứng của bước đó.
5. Phân loại kết quả trung thực:
   - Sản phẩm sai so với “Kết quả mong đợi” → giữ **FAIL**, ghi `tc.defect("mô tả + cách tái hiện + mức độ")`. **Không** sửa mã sản phẩm, **không** nới kỳ vọng để “cho đạt”.
   - Lỗi do script/selector của bạn → sửa script và chạy lại.
   - Không thể kiểm chứng (thiếu môi trường, ngoài khả năng của devserver) → ghi rõ trong `tc.note(...)` và trong kết luận là **chưa kiểm chứng** (không ghi PASS).
6. Dọn dẹp trạng thái dùng chung (ví dụ bật lại kill switch) trong `finally`.
7. Kết thúc bằng một câu trả lời ngắn: **ID · PASS/FAIL/chưa kiểm chứng · đường dẫn `report.md` · lỗi phát hiện (nếu có)**.

**Tiêu chí hoàn thành artifact:** `report.md`, ≥ 1 ảnh mỗi bước, 1 video `.webm` không rỗng và `result.json` đều tồn tại; report không chứa token/secret/nội dung nhạy cảm.
